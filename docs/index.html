Software Architecture as Code for Modern Engineering Teams

OpenC4 is an open-source C4 architecture modeling platform. Model complex enterprise systems with Structurizr DSL, visualize diagrams with sub-50ms React Flow rendering, manage modular multi-file workspaces with drag-and-drop, enforce RBAC with CASL, and validate models via Model Context Protocol (MCP).

Architecture Pipeline

How OpenC4 Works

A unified lifecycle connecting code definitions, interactive visualization, automated quality audits, and universal diagram distribution.

STEP 01

Model as Code

Define systems, containers, components, archetypes, and perspectives using standard Structurizr DSL across modular, decoupled files.

STEP 02

Interactive Studio

Edit in Monaco with sub-50ms React Flow canvas updates. Manage files with drag-and-drop and edit relationships visually.

STEP 03

Automated Governance

Enforce structural rules with the built-in quality linter, derive implied relationships, and validate models via native MCP tools.

STEP 04

Universal Sync & Export

Publish directly to Structurizr instances, automate CI/CD with structurizr-cli, and export to Mermaid for Git markdown.

Capabilities

Built for Modern Architecture Workflows

Everything software architects and engineering teams need to model, govern, and share architecture without proprietary silos.

New Feature

Authentication & RBAC

Zero-dependency authorization powered by CASL. Ships with three pre-seeded accounts (admin, architect, viewer), a 1-click quick role switcher in the studio navbar, and enterprise SSO provider interfaces (OIDC, SAML, LDAP).

New Feature

Multi-File Workspaces & Drag-and-Drop

Deconstruct monolithic models into modular files and directories using !include <file> and !include <dir/>. Drag files between folders with automatic !include AST refactoring, multi-tab state preservation, and 1-to-1 error line mapping.

New Feature

Structurizr DSL Phase 3 & Extended Styles

Support for Archetypes with inheritance, architectural Perspectives (Security, Performance, Cost), custom Terminology overrides rendered on badges, extended node styles (border, opacity, icon), and Themes (AWS, Azure, default).

New Feature

Implied Relationships Engine

Native support for !impliedRelationships directives with configurable strategies. Automatically infers and renders ancestor system-to-system connections when low-level container or component relationships are created.

New Feature

Canvas Relationship Editor

Create, reconnect, reverse direction, or edit relationships directly on the React Flow canvas. Includes quick presets for common descriptions ("Uses", "Publishes to") and technologies (HTTPS, REST, gRPC, SQL) with instant bidirectional DSL sync.

New Feature

Local & Remote MCP Validation

Validate DSL architecture models against any running local or remote Structurizr MCP server. Web Studio provides endpoint testing, latency benchmarking, element counts, and pinpoint syntax error jumps directly to offending lines.

New Feature

Direct Structurizr Publishing & CLI

Publish workspaces directly to external Structurizr instances from the Web Studio via REST Web API or Structurizr MCP. Drop-in replacement for the Structurizr REST API allows seamless CI/CD push and pull via structurizr-cli.

Core Engine

Architecture Quality Linter & Drawer

Automated rule engine detects orphaned elements, missing descriptions, unassigned technologies, and conflicting implied relationships. Dedicated dual-tab inspection drawer displays quality findings and architectural perspectives.

Core Engine

Mermaid & Multi-Format Export

One-click export of C4 views into standard Mermaid diagrams for GitHub READMEs, C4-PlantUML for legacy documentation pipelines, official Structurizr JSON, high-resolution SVG, PNG, and formatted Structurizr DSL.

Running OpenC4 Locally

OpenC4 runs as a lightweight, unified TypeScript application (Hono API backend + React 19 frontend with Vite) backed by local SQLite persistence.

Option A: Node.js & run.sh

Clone the repository and launch the unified server:

Terminal 
git clone https://github.com/gpimblott/openc4.git
cd openc4
./run.sh

Option B: Docker Compose

Start OpenC4 and Structurizr playground containers:

Terminal 
docker compose up --build

Structurizr DSL & Phase 3 Modeling

OpenC4 supports full Structurizr DSL syntax alongside advanced Phase 3 extensions: reusable Archetypes, architectural Perspectives, custom Terminology, and Filtered Views.

workspace.dsl 
workspace "Banking Platform" "Enterprise architecture model" {

    // 1. Workspace-Level Terminology Overrides
    terminology {
        person "Customer Role"
        container "Microservice"
    }

    // 2. Archetypes with Inheritance & Defaults
    archetypes {
        service = container {
            technology "Go, gRPC"
            tag "Backend"
            properties {
                "runtime" "Kubernetes"
            }
        }
        paymentGateway = service {
            technology "Java 21, Spring Boot"
            perspectives {
                "PCI-DSS" "Compliant with Level 1" "Tier-1"
            }
        }
    }

    model {
        customer = person "Retail Customer" "Personal account holder."
        
        banking = softwareSystem "Core Banking" "Handles transfers and accounts." {
            webApp = container "Web Portal" "React Single-Page App" "TypeScript, React" "WebBrowser"
            paymentSvc = paymentGateway "Payment Service" "Processes transactions"
            ledgerDb = container "Ledger Database" "Stores transactions" "PostgreSQL" "Database"
        }

        // 3. Perspectives on Elements and Relationships
        customer -> webApp "Uses" "HTTPS"
        webApp -> paymentSvc "Submits transfers to" "JSON/HTTPS" {
            perspectives {
                "Security" "OAuth 2.0 / MTLS" "High"
                "Performance" "p99 < 80ms"
            }
        }
        paymentSvc -> ledgerDb "Persists transactions" "TCP 5432"
    }

    views {
        systemContext banking "ContextView" {
            include *
            autoLayout lr
        }

        container banking "ContainerView" {
            include *
            autoLayout lr
        }

        // 4. Filtered Views
        filtered "ContainerView" include "Backend" "BackendOnly" "Displays backend services only"

        // 5. Themes & Extended Styles
        theme default
        styles {
            element "Person" {
                shape Person
                background #08427b
                color #ffffff
            }
            element "Database" {
                shape Cylinder
                background #1168bd
            }
        }
    }
}

Modular Multi-File Workspaces & Drag-and-Drop

Large architectures can be split into isolated domain files and subdirectories. Domain teams work on independent DSL files without merge conflicts.

workspace.dsl 
workspace "Enterprise Banking" "Modular architecture model" {
    model {
        !include people.dsl
        !include systems/accounts.dsl
        !include systems/payments.dsl
        // Or include an entire folder:
        // !include systems/
    }
    views {
        systemContext paymentSystem "PaymentContext" {
            include *
            autoLayout lr
        }
    }
}

Studio File Explorer Capabilities

  • Directory Structure: Create nested directories (e.g. systems/, people/) without creating empty placeholder files.
  • Drag-and-Drop File Organization: Drag files directly into folder targets in the sidebar, or drop onto the root banner to move files back to the workspace root.
  • Automatic AST Refactoring: Moving files automatically rewrites corresponding !include paths in workspace.dsl.
  • Multi-Tab Monaco Editing: Switch between files seamlessly with dirty state indicators (•); unsaved in-memory edits are preserved.
  • 1-to-1 Error Line Mapping: If an included file contains a syntax error, the compiler pinpoints the exact file and line, allowing one-click navigation to the issue.

Authentication & Role-Based Access Control (RBAC)

OpenC4 implements isomorphic authorization using CASL, ensuring identical permission enforcement across backend API routes and frontend studio actions.

Capability Admin (admin) Editor (architect) Viewer (viewer)
Explore Diagrams & Catalog ✓ Yes ✓ Yes ✓ Yes
Edit DSL & Save Workspaces ✓ Yes ✓ Yes ✗ Read-only
Publish Workspace Releases ✓ Yes ✓ Yes ✗ No
Manage Users & Assign Roles ✓ Yes ✗ No ✗ No
Regenerate CLI API Keys ✓ Yes ✗ No ✗ No

Enterprise SSO Provider Interface

The auth subsystem supports pluggable identity providers. In addition to local SQLite user authentication with salted scrypt hashing, OpenC4 provides an extensible EnterpriseOidcProvider interface ready for Okta, Azure AD, Keycloak, or LDAP federation.

Automating Architecture in CI/CD with structurizr-cli

OpenC4 implements the official Structurizr Web API specification. Point existing structurizr-cli push and structurizr-cli pull commands directly to OpenC4.

.github/workflows/architecture.yml 
name: Sync Architecture Model
on:
  push:
    paths:
      - 'architecture/**.dsl'

jobs:
  push-diagram:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Push to OpenC4 Platform
        run: |
          docker run --rm -v $(pwd):/usr/local/structurizr structurizr/cli \
            push -url https://openc4.yourcompany.com/api \
            -id 1 \
            -key ${{ secrets.OPENC4_KEY }} \
            -secret ${{ secrets.OPENC4_SECRET }} \
            -workspace architecture/workspace.dsl

Model Context Protocol (MCP) AI Integration

OpenC4 provides a built-in JSON-RPC MCP server at POST /mcp conforming to the Model Context Protocol. AI assistants (Claude Desktop, Cursor, Gemini, Antigravity) can inspect, lint, and query models programmatically.

claude_desktop_config.json 
{
  "mcpServers": {
    "openc4": {
      "command": "curl",
      "args": ["-X", "POST", "http://localhost:8000/mcp"]
    }
  }
}

Available MCP Tools

  • validate_dsl: Validates DSL syntax and returns AST metrics or exact error locations.
  • inspect_workspace: Audits models for orphaned elements, missing descriptions, untyped containers, and implied conflicts.
  • export_diagram: Compiles and exports views into Mermaid, C4-PlantUML, or Structurizr JSON.
  • query_model: Searches systems, containers, components, and relationships programmatically.

Exporting Mermaid for Markdown & Git Repositories

Export C4 diagrams into Mermaid markdown syntax with one click. Embed diagrams directly into GitHub/GitLab READMEs, PR descriptions, Notion pages, and static docs.

README.md 
```mermaid
C4Context
    title System Context Diagram for Internet Banking

    Person(customer, "Personal Banking Customer", "Personal accounts holder")
    System(bankingSystem, "Internet Banking", "Allows customers to view balances and transfer funds")
    System_Ext(coreBanking, "Core Banking System", "Central financial record ledger")

    Rel(customer, bankingSystem, "Uses", "HTTPS")
    Rel(bankingSystem, coreBanking, "Queries balances", "XML/HTTPS")
```

FAQ

Frequently Asked Questions

What is OpenC4?
OpenC4 is an open-source C4 architecture modeling tool. It allows software architects, engineering leaders, and developers to model systems as code using the C4 model (Context, Container, Component, Deployment) and visualize them in real-time with an interactive web studio.
Can I use existing Structurizr DSL files and structurizr-cli pipelines?
Yes. OpenC4 provides full compatibility with the Structurizr DSL, Structurizr JSON schemas, and implements the official Structurizr Web API specification. You can point structurizr-cli push and structurizr-cli pull directly to OpenC4 without modifying your existing scripts.
How does multi-file workspace support work with !include?
OpenC4 features a recursive preprocessor that resolves both individual file includes (!include people.dsl) and full directory includes (!include systems/). Moving files in the studio file explorer automatically refactors !include statements in workspace.dsl, and compiler diagnostics map errors directly to the source file and line.
How does OpenC4 integrate with AI models via MCP?
OpenC4 exposes a JSON-RPC Model Context Protocol (MCP) server at POST /mcp. AI agents such as Claude, Cursor, Gemini, and Antigravity can invoke tools to validate DSL syntax, audit model quality, query relationships, and export diagrams. The Web Studio also includes an in-browser MCP validation modal to test models against any local or remote MCP server.
What license does OpenC4 use?
